## 1. 문제 / 목표 / 성공지표

### 문제

현재 앱의 모든 화면은 **가정(시뮬레이션)** 위에 서 있다. 사용자가 실제로 보유한 주식은
어디에도 입력할 곳이 없다:

- 시뮬레이터 포트폴리오는 **비중(%) 기반**이다(`PortfolioPersistedState.weightByTickerId`,
  shared/types/snowball.ts:33-39). "SCHD 120주"라는 사실을 표현할 수 없다.
- Goal 페이지(`/dividend/goal`)의 "현재 월배당"은 **시뮬레이션 파생값**(직전 12개월 세후 평균,
  `currentMonthlyDividend` — shared/lib/snowball/SnowballGoal.ts:159)이다. "내 현재 상태"가 아니라
  "내 가정이 옳았다면 지금쯤 받고 있을 값"이다. ROADMAP-v2 부록이 이를 **과도기 정본**으로 명시했다.
- 배당 캘린더는 티커 **선택**만 저장한다(수량 없음) — v2 §7의 "이번 달 예상 입금 $184"를 계산할 수 없다.

즉 v2 핵심 철학("사용자는 계산하러 오지 않는다 — 자신의 성장·진행률을 확인하러 재방문한다")의
전제인 **"현재 상태"라는 데이터 축 자체가 없다.** Portfolio → Goal → Simulator → FIRE로 이어지는
자동 계산 파이프라인(v2 데이터 구조 표)의 첫 칸이 비어 있는 상태다.

### 목표

1. 사용자가 **티커 + 보유 수량만 입력**하면(사용자 입력 최소화), 나머지 7개 지표
   (자산 가치 · 연배당 · 월배당 · 배당수익률 · 세후 배당 · 이번 달 예상 배당 · 다음 배당 지급일)를
   **전부 자동 계산**해 보여준다.
2. 이 데이터가 재방문의 이유가 된다 — 시세·환율이 바뀌면 다음 방문 때 숫자가 바뀌어 있다.
3. Goal·Simulator로 이어지는 **허브 연결점**을 만든다(단, Goal 실측 교체 자체는 후속 — §6-⑥).

### 성공지표 (GA4 — 신규 이벤트는 §5 US7 참고)

| 지표 | 측정 | 목표(가설) |
|---|---|---|
| 활성화 | `portfolio_view` → 같은 세션 내 첫 `portfolio_holding_saved` 전환율 | ≥ 40% (가설 — 사전 데이터 없음) |
| 완주 | `portfolio_summary_view`(요약 지표 노출 1회) 도달율 | 보유 입력자의 ≥ 90% |
| 재방문 | `RETURN_VISIT` 사용자 중 `portfolio_view` 발생 비율 추이 | 출시 4주 후 상승 추세 확인 |
| 허브 전환 | `CTA_CLICK{cta_name: portfolio_to_simulator}` 클릭률 | 요약 도달자의 ≥ 15% (가설) |
| 데이터 신뢰 | `OPERATION_ERROR{operation: portfolio_*}` 발생율 | 세션 대비 < 1% |

> 사전 근거 데이터 없음 — 위 수치는 전부 **가설**이며, 출시 후 analytics-analyst가 실측으로 보정한다.

## 2. 스코프

### 이번에 하는 것

1. **보유 입력**: 티커 검색/선택 + 보유 수량 입력·수정·삭제. 시장 데이터 유니버스(50종) 자동 채움.
2. **자동 계산 요약**: 7개 지표(§4 정의) — 전부 순수 함수, 브라우저 계산.
3. **영속**: 보유 목록의 로컬 저장·복원(왕복 테스트 포함). 클라우드 동기화는 v1 제외(§6-②).
4. **허브 연결 CTA**: "이 포트폴리오로 시뮬레이션" — 기존 프리필 커밋 계약(decisions
   [2026-07-27] 프리필) 위에서 시뮬레이터로 이동. 역방향 없음.
5. **계측**: §5 US7의 GA4 이벤트.

### 비목표 (스코프 누수 방지 — 이번에 하지 않는 것)

| 비목표 | 사유 |

## 4. 자동 계산 정의 (7개 지표 — 전부 검증 가능한 식)

기호: 종목 h = { 티커, 수량 q(h), 가격 P(h) [USD], 배당률 y(h) [%], 지급월 M(h), 지급횟수 n(h) },
환율 FX [KRW/USD], 세율 t [%]. 주당 연배당 DPS(h) = P(h) × y(h)/100 (시뮬 dps0 정의와 동일 —
SnowballSimulation.ts:41).

| # | 지표 | 정의 | 비고 |
|---|---|---|---|
| 1 | 현재 자산 가치 | Σ q(h) × P(h) × FX | 원화 환산. 환율 불가 시 §6-④ 폴백 |
| 2 | 연배당(세전) | Σ q(h) × DPS(h) × FX | 현재 배당률 스냅샷 기준 — **성장 미반영**(Portfolio는 "현재 상태", 미래는 Simulator 소관) |
| 3 | 월배당(세전) | 연배당 ÷ 12 | **평균** 정의(Goal D1·연 해상도 `annualDividend/12`와 같은 정의 계열). "매달 이만큼 입금"이 아님을 카피로 구분 — 실제 입금은 #6이 답한다 |
| 4 | 배당수익률 | 연배당 ÷ 자산가치 × 100 | 가중평균. FX가 분자·분모에서 소거 — 환율 실패에도 계산 가능 |
| 5 | 예상 세후 배당 | 세전 × (1 − t/100) | 단일 세율, 기본값 §6-⑦ |
| 6 | 이번 달 예상 배당 | Σ{h: 이번 달 ∈ M(h)} q(h) × (연DPS(h) ÷ 회수(h)) × FX | 회수(h) = `payoutMonths` 있으면 그 길이, 없으면 frequency 기반 n(h). **불변식: 12개월치 #6의 합 = #2** |
| 7 | 다음 배당 지급일 | 종목별: M(h)에서 오늘 이후 가장 가까운 지급월(연 경계 순환). `payoutMonthsSource='pay'` + `estimatedPayDayByMonth` 있으면 "N월 D일쯤(추정)", 아니면 "N월 중(추정)" | **날조 금지**(캘린더 확정 결정과 동일) — 일자를 지어내지 않는다. 'ex' 소스는 ±1개월 오차 카피 |

공통 규칙:
- `payoutMonths` 없는 종목('none' 1종 + 유니버스 밖 수동 티커)은 #6·#7에서 **제외하고 제외 사실을
  화면에 표시**한다(무음 제외 금지 — user-profile "이유 표시" 요구).
- 모든 표기는 통화 토글(기존 `effectiveDisplayCurrencyAtom` 계열)을 따르되, 계산 정의는 §6-④.
- 시세 기준일(`MARKET_DATA_AS_OF`)을 화면에 명시한다(기존 `MarketDataAsOf` 관례).

## 5. 유저스토리 + 수용 기준 (AC)

### US1 — 보유 입력: "SCHD 120주 있어요"

배당 투자자로서, 내가 가진 종목과 수량만 입력하면 나머지는 앱이 알아서 계산해 주길 원한다.

- **AC1-1**: 유니버스 50종의 티커를 검색·선택하면 가격·배당률·지급 주기·지급월이 자동으로 채워지고,
  사용자가 추가 입력할 것은 **수량 하나**다.
- **AC1-2**: 수량은 양수만 허용, 0·음수·NaN·Infinity는 저장 자체가 거부되고 이유가 표시된다.
  (소수점 허용 여부·자릿수는 §6-⑤ 결정 후 AC 확정)
- **AC1-3**: 같은 티커를 두 번 추가하면 별도 행이 아니라 기존 행 수정으로 안내된다(중복 행 금지).
- **AC1-4**: 보유 행의 수량 수정·삭제가 가능하고, 삭제는 실수 복구 여지(확인 단계 또는 실행 취소)를 가진다.
- **AC1-5** (유니버스 밖 티커 — §6-⑧ 결정 조건부): 미커버 티커는 가격·배당률 수동 입력으로 추가할
  수 있되, 해당 행과 요약에 "수동 입력" 표기가 남고 #6·#7 계산에서 빠진다는 안내가 보인다.

### US2 — 자동 계산 요약: "내 배당 머신의 현재 스펙"

- **AC2-1**: 보유 1종 이상이면 §4의 #1~#5가 즉시 표시된다(저장 버튼·재계산 버튼 없음 — 입력 즉시 반영).
- **AC2-2**: #1~#7 각 값은 §4의 식과 일치한다 — 단위 테스트로 봉인(순수 함수 계층).
- **AC2-3**: 시세 기준일("2026-07-25 기준")과 환율 기준 시각이 화면에 표시된다.
- **AC2-4**: 월배당(#3)과 이번 달 예상 배당(#6)이 다른 개념임이 화면에서 구분된다
  (분기 지급 종목만 보유하면 #3 > 0인데 #6 = 0인 달이 존재한다 — 이 상태가 버그처럼 보이면 안 된다).
- **AC2-5**: 보유 0종이면 요약 지표 대신 빈 상태 안내(첫 입력 유도)가 보인다. 0원·NaN 표기 금지.

### US3 — 이번 달 예상 배당·다음 지급일: "이번 달엔 얼마 들어오지?"

- **AC3-1**: 이번 달이 지급월인 종목들의 회당 지급액 합이 #6 정의대로 표시된다.
- **AC3-2**: 12개월치 #6의 합 = #2(연배당·세전)가 테스트로 봉인된다(불변식).
- **AC3-3**: 다음 지급일 표기는 소스 등급별 3단계다 — pay+일자: "8월 14일쯤(추정)" /
  월만: "9월 중(추정)" / 정보 없음: "지급월 정보 없음". **일자·월을 지어내지 않는다.**
- **AC3-4**: #6·#7에서 제외된 종목이 있으면 "n종 제외" 안내가 보인다(무음 제외 금지).

### US4 — 영속: "다음에 와도 그대로"

- **AC4-1**: 보유 목록은 로컬에 저장되고 재방문·새로고침 후 복원된다(저장 위치는 §6-② 결정).
- **AC4-2**: 저장→복원 왕복 테스트가 있다(스키마 버전 필드 포함 — 이후 확장 대비).
- **AC4-3**: 저장소 읽기 실패(프라이빗 모드·잠금)는 error 상태로 표면화된다 — 무음 실패 금지,
  기존 데이터를 삭제·덮어쓰기하지 않는다(`useGoalScenario`의 read-failed 관례).
- **AC4-4**: 시뮬레이터의 기존 저장 데이터·공유 URL·클라우드 payload는 **바이트 하나 안 바뀐다**
  (기존 스키마 무변경 — 하위 호환 리스크 0으로 설계).

### US5 — 허브 연결: "이 포트폴리오로 미래를 계산해줘"

- **AC5-1**: "이 포트폴리오로 시뮬레이션" CTA가 있고, 클릭하면 시뮬레이터로 이동하며 현재 자산
  가치(#1)와 종목 구성이 프리필된다 — 커밋은 반드시 **기존 프리필 계약**(location.state →
  하이드레이션 게이트 하위 커밋)의 확장으로만 한다. 전역 atom·저장 payload 직접 쓰기 금지
  (pitfalls 🔴 3경로). 프리필 확장 범위는 state-engineer 안전 판정이 선행 조건.
- **AC5-2**: 보내는 쪽·받는 쪽이 같은 sanitize를 쓴다(신뢰 불가 location.state 원칙).
- **AC5-3**: 역방향(시뮬 비중 → Portfolio 수량) 변환은 **없다** — 수량 정보가 없어 날조가 되기 때문.

### US6 — 통화: "달러 자산인데 원화로 보고 싶어"

- **AC6-1**: 요약 지표는 기존 표시 통화 토글을 따른다(원 기본).
- **AC6-2**: 환율 상태가 error(보여줄 값 없음)면 원화 환산 값 대신 **달러 원값 + "환율 조회 실패"
  안내**가 보인다 — 가짜·낡은 환율로 원화를 위장하지 않는다(§6-④ 결정 조건부).
- **AC6-3**: stale이면 값은 보여주되 실제 as-of가 표시된다(기존 ExchangeRateWidget 관례).
- **AC6-4**: 배당수익률(#4)은 환율 실패와 무관하게 항상 계산된다(FX 소거).

### US7 — 계측 (GA4 신규 이벤트)

- **AC7-1**: `portfolio_view`(진입 1회, holdings_count·has_holdings),
  `portfolio_holding_saved`(action: add|edit, covered: boolean),
  `portfolio_holding_deleted`,
  `portfolio_summary_view`(세션 1회, holdings_count·covered_count·value_bucket)이
  `ANALYTICS_EVENT` 택소노미(용도 주석 포함)에 추가된다.
- **AC7-2**: 허브 CTA는 기존 `CTA_CLICK` 재사용(cta_name: `portfolio_to_simulator`).
- **AC7-3**: 저장·읽기 실패는 기존 `OPERATION_ERROR` 재사용(operation: `portfolio_*`).
- **AC7-4**: 금액 원값은 이벤트에 싣지 않는다 — bucket만(기존 value_bucket 관례).

### 공통 제약 (전 스토리)

- 카피에 "눈덩이/스노우볼" 비유 금지. 투자 자문형 문구 금지(추천·매수 유도 없음 — 시뮬레이터·기록 도구).
- 해시 라우팅 금지(경로 기반).
- 접근성: 입력 폼 라벨·에러는 시맨틱 연결, 추정 표기는 색만이 아니라 텍스트로.

## 6. 사용자 확인 필요 결정 (에스컬레이션 — 각 항목 PM 권고 포함)

> 이 8건이 닫혀야 구현 위임이 가능하다. 권고는 참고용 — 최종 결정은 사용자.

### ① 시뮬레이터 포트폴리오와의 관계: 별도 도메인인가, 변환/연동인가

- **사실**: 시뮬 포트폴리오는 시나리오 탭마다 있는 비중(%) 구조(하위 호환 자산). Portfolio는 수량 구조.
- **옵션 A (권고)**: **별도 도메인 + 단방향 프리필**(Portfolio → 시뮬: 자산가치→초기투자금,
  구성→비중 환산). 역방향 없음. v2 파이프라인(Portfolio→Goal→Simulator) 방향과 일치하고,
  시뮬 스키마 무변경이라 하위 호환 리스크 0.
- **옵션 B**: 시나리오 탭에 수량 필드를 추가해 한 도메인으로 통합 — 영속·공유·클라우드·OG까지
  스키마 전파, 하위 호환 왕복 부담 최대. **비추천.**
- 부속 결정: 프리필이 시뮬레이터의 어느 시나리오 탭에 꽂히는가(활성 탭 덮어쓰기 vs 새 탭 생성).
  탭 생성은 비로그인 1탭 게이트(pitfalls [2026-07-19])와 얽힌다 — **권고: 새 탭 생성 + 게이트 존중**
  (비로그인이면 로그인 유도 프롬프트 재사용).

### ② 저장 스키마 위치와 클라우드 동기화 포함 여부

- **사실**: 기존 appState payload는 클라우드 3-way 동기화(base 해시)의 단위다. Main 밖에서 그
  payload에 쓰는 3경로 전부 위험 판정 완료(pitfalls 🔴). 캘린더는 별도 IndexedDB DB 선례.
- **옵션 A (권고)**: **신규 IndexedDB DB(`snowball-portfolio`) + v1 로컬 전용.** 기존 동기화
  엔진과 완전 격리 — 하위 호환·발산 리스크 0. 클라우드 동기화는 **후속 미션**(동기화 엔진의
  두 번째 payload 레인 설계가 그 자체로 한 미션 크기).
- **옵션 B**: 처음부터 클라우드 포함(사용자의 DB 중심 편의 선호 — user-profile). 단 이 경우
  Portfolio 페이지에 전용 sync 훅·base 해시·충돌 정책까지 이번 스코프에 들어와 출시가 늦어진다.
- **트레이드오프 정직 고지**: 옵션 A는 기기 간 Portfolio가 안 맞는다(시뮬 데이터는 맞는데
  보유 데이터만 이 기기 것). v1 화면에 "이 기기에만 저장됨" 안내를 넣는 조건으로 A 권고.

### ③ 경로·내비 배치

- **권고**: 경로 `/portfolio`(최상위 — `/dividend/*`는 파생 화면 계열, Portfolio는 데이터 축이라
  형제가 아님. 갤러리 `/community/portfolio`와 충돌 없음 확인). 라벨 **"내 포트폴리오"**
  (갤러리 "포트폴리오"와 혼동 방지 — "내 ~"는 my-posts 선례). 위치는 **시뮬레이터 바로 다음,
  목표 달성 앞**(v2 파이프라인 순서 = Simulator·Portfolio·Goal이 연속으로 보이게).
- **우려 공유**: 내비가 7항목이 된다(모바일 스크롤 줄 밀도). 대안: ETF 소개를 뒤로 밀거나(현행
  유지 가능) 커뮤니티 2항목 통합은 **별도 결정** — 이번 미션에서 임의 재배치 금지.

### ④ 통화 정책: 환율이 처음으로 "계산 입력"이 된다

- **사실**: 유니버스 50종 전부 USD. 수량×가격은 USD 자산이라 원화 표시에 환율 곱이 **필수**다.
  기존 원칙 "계산은 원화·표시만 통화 전환"은 가격 단위가 소거되는 시뮬 구조의 산물 — Portfolio에는
  그대로 적용 불가. 기존 FX 계약은 "표시 전용, 시뮬 입력·저장·공유 불침투"(exchangeRate.ts:8).
- **권고**: 원칙을 이렇게 확장한다 — **"저장은 통화 중립(수량만 저장, 환산값 저장 금지),
  환산은 표시 계층에서 조회 시점 환율로"**. 즉 FX는 여전히 영속에 침투하지 않고, 요약 지표
  계산이 표시 계층으로 온다. 환율 실패 시 **달러 원값 + 실패 안내**(가짜 환율 금지 유지, AC6-2).
- 부속: 시뮬 프리필(AC5-1)의 초기투자금은 원화 필드다 — 프리필 시점 환율로 환산해 넘기고
  환산 기준을 화면에 밝힌다. 환율 실패 시 프리필 CTA는 비활성 + 이유 표시.

### ⑤ 소수점 주식(fractional shares) 허용 여부

- **권고**: **허용, 소수 4자리까지**(국내 증권사 해외주식 소수점 매매가 보편 — 0.0001주 단위가
  업계 관행). 정수 강제는 소수점 투자자의 입력을 막아 활성화 지표를 직접 깎는다.
- 반영: AC1-2의 검증 규칙에 "소수 4자리 초과 반올림 or 거부" 확정 필요(권고: 입력 단계 반올림 안내).

### ⑥ Goal "현재 월배당" 실측 교체를 이번 미션에 포함하는가

- **사실**: ROADMAP-v2 부록이 "Portfolio 랜딩 시 실측 교체"를 명시. 그러나 Goal의 현재·달성률·
  달성월은 **같은 식에서 나온다는 불변식**으로 묶여 있다(SnowballGoal.ts:16-25). 현재값만
  실측(수량 기반)으로 바꾸면 "현재 82만 / 달성월 계산은 시뮬 기준" — 두 계열이 섞여 달성률과
  달성월이 서로 안 맞는 화면이 된다. 상태 7종·폴백(Portfolio 미보유 사용자) 재설계가 필요하다.
- **권고**: **후속 미션으로 분리.** 이번 미션은 ①실측 월배당을 반환하는 순수 함수(§4 #2·#5)를
  Goal이 그대로 소비할 수 있는 형태(`shared/lib/` 공유 계층)로 두고 ②`useGoalScenario.ts:240`
  한 곳이 유일 교체 지점임을 확인하는 데까지만. 교체 미션의 선행 질문("현재=실측일 때 달성률·
  달성월 정의를 어떻게 다시 묶나")은 그 미션의 pm-po 몫으로 넘긴다.
- **옵션 B**: 이번에 포함 — Portfolio 출시와 Goal 재설계가 한 덩어리가 돼 출시 지연 + Goal 7종
  상태 회귀 리스크. 비추천.

### ⑦ 세후 계산의 세율

- **사실**: 시뮬 세율은 단일 `taxRate`(정규화 기본 15.4%). 유니버스는 전부 미국 종목이라 원천징수는
  15%이고, 국내 과세는 개인 상황(종합과세 여부)에 따라 다르다.
- **권고**: v1은 **단일 조정 가능 세율, 기본값 15.0%**(미국 원천징수 — 전 종목 USD인 현실 반영)
  + "간이 계산" 고지. 시뮬레이터 기본값(15.4%)과 다르다는 점을 사용자에게 확인받을 것 —
  일관성(15.4)을 택할지 정확성(15.0)을 택할지는 제품 결정. 어느 쪽이든 세무 자문처럼 보이는
  카피 금지.

### ⑧ 유니버스 밖 티커 처리

- **사실**: 자동 계산은 50종에서만 성립. AAPL·MSFT·TSLA·국내 주식 전부 미커버 — 실사용자
  포트폴리오의 상당 부분이 "티커+수량"만으로는 입력 불가할 가능성이 높다.
- **권고**: **수동 폴백 허용**(AC1-5 — 가격·배당률 직접 입력, "수동" 표기, #6·#7 제외) +
  **유니버스 확장을 별도 백로그**로(ticker-data-curator, 시총 상위 배당주·국내 배당주 추가).
  수동 폴백 없이 출시하면 첫 입력에서 막힌 사용자의 이탈이 활성화 지표를 무너뜨린다(가설).
- **옵션 B**: v1은 유니버스 50종만(스코프 최소) — 출시가 빨라지지만 위 이탈 리스크. 차선.

## 7. 우선순위·마일스톤·위임 계획 (결정 확정 후 실행)

우선순위 근거: ①데이터 손상·계산 오류 방지 > ②핵심 퍼널 > ③신규 기능 순서에 따라,
**순수 계산 계층과 영속 왕복을 먼저 봉인**하고 화면을 그 위에 얹는다.

| 단계 | 내용 | 담당 | 산출물 게이트 |
|---|---|---|---|
| M0 | 도메인 모델 + §4 순수 계산 함수(7지표·불변식) + 단위 테스트 | simulation-engineer | AC2-2, AC3-2 테스트 그린 |
| M1a | 영속(신규 IndexedDB, 스키마 v1, 왕복 테스트) | state-engineer | AC4-1~4 |
| M1b | 화면 설계(입력 폼·요약·추정 표기·빈 상태·반응형) — M1a와 병렬 | ui-ux-designer → frontend-engineer | AC1·2·3·6, 카피 금지어 검수 |
| M2 | 허브 CTA(프리필 계약 확장 — state-engineer 안전 판정 선행) + 계측 | state-engineer → frontend-engineer | AC5, AC7 |
| 검증 | 전 AC 회귀 + `npm run verify` | qa-tester → reviewer | AC 전체 대비표 |

- 다층(계산·상태·화면) 실행 조율은 orchestrator에 위임(스펙 = 이 문서 + §6 확정 결정).
- 배포는 [[ask-before-deploy]] — 사용자 승인 후에만.

## 8. 리스크·기존 함정 연결 (구현 브리핑에 반드시 주입)
