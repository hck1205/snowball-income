## 2. 중단 작업의 진실 — "헤더 이동"은 중단이 아니라 **철회**였다

처음 판단은 *"주요 지수 스트립을 앱 헤더로 옮기다 말았다"* 였다. **틀렸다.**
인수 트랙이 파일 수정 시각과 CDP 실측으로 반증했다:

- `01:55` 랜딩에서 제거 → `02:02` 헤더 변형 제작 → `02:04` 헤더 배선 → **`02:06~07` 세 페이지 본문으로 재배치**
  (주석에 "헤더에 얹었다가 되돌렸다 — 2026-08-02 사용자 결정" 서명) → `02:11` 마무리
- `AppHeader.tsx` 에 남아 있던 diff 1줄은 add→remove 잔여물이었다
- **헤더에는 물리적으로 자리가 없다**: 헤더 nav 트랙 902px(1440·1280) vs 스트립 6칸 필요 폭 **1,190px**.
  전폭 한 줄을 얹으면 헤더 높이가 65→90px 로 `headerprobe` 의 `SINGLE_ROW_MAX_HEIGHT=80` 위반

**현재 상태**: 주요 지수는 `/simulator` · `/dividend/portfolio` · `/dividend/calendar` **3화면에 살아 있고**,
`/`(랜딩)에는 없다. 이것이 최신 결정 상태다.

### 함께 처리한 것

- **🔴 미발견 버그 수정** — 시세를 그리는 3페이지의 **문서 가로 오버플로**(390px 에서 문서 폭 390→**679**).
  스크롤러 안 `position: absolute` 시각 숨김 문장이 컨테이닝 블록을 못 찾아 x≈650px 에 남아 있었다.
  화면엔 아무것도 안 보이는데 페이지만 옆으로 밀리는 형태였다. `headerprobe` **6건 실패 → 30/30 통과**.
- **§D-3 방향 글리프** — 등락률에 ▲/▼ 를 부호 왼쪽에 세웠다(색 단독 채널 제거).
- **§D-6 메타 카피** — `전일 대비 · 실시간이 아닌 참고용 시세`.
- 거짓 주석 6곳 정리 + 재발 방지 가드 신설(`test/shared/marketIndexStripPlacement.test.ts`).

## 3. 가계부 고도화 — 무엇이 생겼나

정본 스펙: **`docs/ledger-advanced-spec-2026-08-02.md`** (결정 19건 · 수용기준 33건 · 리스크 10건).
아래는 요약이다. 왜 그렇게 정했는지는 스펙의 해당 결정 항목(D1-1 …)에 근거가 있다.

### 3-1. 탭별 조회 (L1)

- 연결 정보 줄에 **탭 선택 드롭다운**. 탭이 1개면 이름만 표시한다(선택지 없는 select 금지).
- **탭마다 열 매핑이 따로 저장된다** — 스키마 변경 0. `StoredSheetLink` 가 원래 `spreadsheetId + sheetId` 단위였다.
- 매핑이 있는 탭 → 원클릭 전환. 없는 탭 → 기존 매핑 화면 재사용 후 저장.
- 🔴 **탭 전환 안전장치**: 폼이 열려 있거나 **저장 실패 대기열**이 있으면 전환을 막고 사유를 텍스트로 보여 준다.
  막지 않으면 재시도가 **다른 탭에 행을 기록**한다(추가에는 행 참조가 없어 기존 가드가 못 막는다).

### 3-2. 외부 수정 확인 (L2)

> ⚠ **"화면에서 직접 수정"은 이미 구현돼 있었다** — 수정 모달·필드 단위 패치·동시 편집 충돌 감지·실패 잔류까지.
> 실제 공백은 "확인" 쪽이었다. 그래서 인라인 셀 편집은 만들지 않았다(스펙 비목표).

- 목록 카드 헤더에 **`09:30 기준`** + **새로고침 버튼**(상시).
- **창 포커스 복귀 + 마지막 읽기에서 5분 경과** 시에만 자동 재확인. 🔴 **폴링·인터벌 타이머 0개**
  (Sheets 읽기는 429 가 실제로 나는 자원이다).
- 폼·삭제 다이얼로그가 열려 있으면 자동 재조회하지 않는다. 월 커서도 바꾸지 않는다.
- 재조회 결과가 직전과 다르면 "시트 내용이 갱신되었습니다" 안내(라이브 리전). **행 단위 diff 는 만들지 않았다**
  — 물리 삭제가 행 번호를 밀면 옛 행과 새 행의 대응이 원리적으로 불확실해서, 정확한 척하는 diff 는 날조다.
- 히어로가 중복해서 말하던 메타 줄을 삭제했다. 배치가 정리됐다:
  **탭 줄 = 어느 장부 / 목록 헤더 = 언제 기준 / 월 네비 = 어느 기간.**

### 3-3. 두 가계부 블렌딩 (L3)

- 저장된 링크가 **2개 이상일 때만** 진입점이 보인다. `/ledger` 안의 **보기 모드 전환**이다(새 라우트 없음).
- 설정에서 두 링크를 고르고 **라벨**을 붙인다(기본 '가계부 1'/'가계부 2').
  🔴 시트 파일명·탭 제목을 라벨 기본값으로 쓰지 않는다 — 준PII 를 로컬에 저장하는 뒷문이 된다.
- 통합 뷰: 날짜 오름차순 합친 목록(행마다 **출처 배지** = 라벨 텍스트 + 테두리 모양) + **합산 3숫자** +
  **출처별 소계 2줄**("가계부 1: 수입 X · 지출 Y") — "누가 얼마 썼는지"는 이 소계가 답한다.
- 🔴 **읽기 전용.** 추가·수정·삭제 버튼이 없다. 각 행의 수정은 "이 가계부에서 열기"로 단일 뷰로 전환해서 한다
  (쓰기 안전 체계가 링크 단위라, 두 링크가 섞인 화면의 쓰기는 오류 표면이 두 배가 된다).
- 🔴 **반쪽 실패를 합계로 위장하지 않는다.** 한쪽 읽기가 실패하면 합산 숫자를 **만들지 않는다** —
  타입 자체에 `summary` 필드가 없는 갈래(`partial`)라 화면이 실수할 수 없다.
- **분류는 합치지 않는다**(원문 그대로, 출처로 구분). **통화 변환도 하지 않는다** —
  앱이 통화 차이를 감지할 방법이 없어 "두 가계부는 같은 통화를 전제합니다"를 도움말로 명시했다.

**권장 구성**: 부부가 **시트 하나를 공유하고 각자 탭을 쓰는** 방식(D3-1). 이 경우 권한 문제가 애초에 없다.
서로 다른 시트도 코드는 동일하게 동작한다(§6-2 참고).

### 3-4. 배당 블렌딩 (L4)

- 요약 카드 **아래 형제 카드** "배당 겹쳐 보기". **기본 꺼짐** 토글, 상태는 새 로컬 키에 저장.
- 지표 3개(보고 있는 달 기준, 세후 원화):
  1. **이번 달 예상 배당** — 지급월 미상 종목이 있으면 "N종은 포함되지 않습니다"를 함께 표시
  2. **지출 커버율** — 배당 ÷ 그 달 지출. 🔴 지출이 0 이면 **표시하지 않는다**(0 나눗셈을 100%로 위장 금지)
  3. **배당이 감당하는 분류** — 작은 분류부터 누적해 배당 이내에 들어오는 분류 이름("통신비·구독료를 덮습니다")
- 🔴 **시트에 쓰지 않는다.** 화면 오버레이 전용이다. 앱이 **추정치**를 사용자 자산에 기입하면 되돌릴 수 없고,
  사용자가 실제 입금을 이미 기록했다면 이중 계상이 된다.
- 🔴 **월 요약 3숫자에 합산하지 않는다.** 합산하면 "가계부 총합"의 정의가 둘이 된다.
- 출처는 **`/dividend/portfolio` 의 실보유**다(시뮬레이터 구성이 아니다 — 그건 가설 시나리오다).
  보유가 없으면 숫자 대신 안내 1줄. 환율을 못 불러오면 원화 환산·커버율을 **숨기고** USD 원값만 보여 준다.
- 블렌딩 뷰에서는 배당 카드를 **표시하지 않는다**(V1) — "우리 가계" 대비 "내 포트폴리오"의 귀속이 충돌한다.

### 리뷰에서 나온 것

`reviewer` 가 **Blocking 1 · Major 1**을 잡았고 **둘 다 수정 완료**다.

  대기열이 있는 상태에서 블렌딩을 거치면 **다른 탭에 행이 기록되는** 경로가 열려 있었다.

## 6. 🔴 아침에 결정해 주셔야 할 것

### 6-1. 주요 지수를 헤더에 넣는 시도를 완전히 접을까?

- 코드에 **소비처 0인 죽은 경로**가 남아 있다: `MarketIndexStrip` 의 `variant='header'` 와 `shortLabel`.
  (이전 세션이 헤더용으로 만들었다가 되돌리며 **삭제하지 않고 보존**했다.)
- 또 **기록이 정면으로 충돌한다**: 컴포넌트 주석은 "헤더에 넣지 마라(실측으로 되돌렸다)"인데,
  랜딩 테스트 주석은 "사용자 결정으로 헤더 로고↔로그인 사이로 옮긴다"고 적혀 있다.
- **접는다면** → 죽은 경로 2개를 지우고 주석을 하나로 통일한다.
  **다시 시도한다면** → 헤더 높이 예산(현재 상한 80px)을 먼저 올릴지 합의해야 한다. 폭이 250px 부족하다.

### 6-2. 별개 시트 경로 실측 (유일한 미확인 전제)

앱의 구글 권한은 `drive.file` 이라, 기존 시트를 여는 유일한 길이 **피커**다.
**배우자가 공유해 준 시트가 피커 목록에 나오는지 실측하지 못했다** — 구글 계정 2개가 필요하다.

- 실측 성공 → 별개 파일 블렌딩이 그대로 정식 지원된다(코드는 이미 두 경로를 구분하지 않는다).
- 실측 실패 → **"같은 시트에 탭 2개"** 권장 경로로 안내하면 되고, 기능은 그대로 성립한다.
- 어느 쪽이든 **코드 변경은 필요 없다.** 안내 문구도 이미 두 경로를 다 열어 두는 조건문으로 썼다.

👉 아침에 구글 계정 2개로 5분이면 확인된다. 결과를 스펙 §8 에 적어 주시면 미확인이 사라진다.

### 6-3. 배포 여부

🔴 **커밋·푸시·PR·머지를 하지 않았다**(`ask-before-deploy` 확정 결정).
브랜치 `feat/legal-and-ledger-enable` 에 **미커밋 변경 163개+** 가 쌓여 있고,
가계부 외 트랙(랜딩·티커 SEO·법무)의 변경이 **섞여 있다.**
배포하려면 `ship` 스킬로 **기능 트랙별로 갈라** 커밋해야 한다 — 통째로 커밋하지 말아 달라.

## 7. 남은 것 / 후속 제안 (전부 선택 사항)

| # | 항목 | 비고 |
|---|---|---|
| 1 | **다른 파일의 가계부로 "열기"** | 지금은 지금 연결된 스프레드시트의 탭에만 전환 버튼을 준다. 다른 파일은 `drive.file` 특성상 피커를 다시 거쳐야 해서 이유 문장만 띄운다. 열려면 `useLedgerConnection` 에 "특정 spreadsheetId 로 재연결" API 가 필요하다 |
| 2 | **매핑 화면의 "이전 탭으로 돌아가기"** | 매핑 없는 탭으로 전환하면 탈출구가 "다른 시트 고르기"뿐이다. 수용기준 밖이라 만들지 않았다 |
| 3 | **GA 계측 4종** | 소스 가드가 `pages/Ledger/**` 에서 GA 를 0건으로 잠그고 있다(시트·탭 이름 유출 방지). 계측을 붙이려면 가드 완화 + 택소노미 갱신이 먼저다 |
| 4 | **429 예산 문서 편차** | 스펙은 "블렌딩 진입 시 2회"인데, 제목을 모르는 스프레드시트가 섞이면 파일당 메타 조회 1회가 더 든다(A1 범위를 만들려면 탭 제목이 필요한데 준PII 라 저장하지 않는다). 전부 사용자 액션 바운드·캐시됨 — 스펙 §7 표만 현실에 맞게 고치면 된다 |
| 5 | **기존 코드 결함(이번 세션 산출 아님)** | 토큰이 조용히 만료된 채 재시도하면 아무것도 쓰지 않고 "저장했습니다"로 낭독되며 대기열 초안이 사라진다(`useLedgerWrite.ts:241,423`). 별도 티켓 권고 |
| 6 | **반응형 실측** | 블렌딩·배당 카드의 390px 실측을 못 했다. `/ledger` 가 구글 자격증명 게이트 뒤라 자동 도달이 불가능하다. 구조는 DOM 단정으로 잠갔다 |
| 7 | **인덱스 갱신** | `npm run index` 가 stale 이다(무해). 커밋 시 pre-commit 훅이 자동으로 돌린다 |
