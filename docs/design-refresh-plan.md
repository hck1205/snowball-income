## 1. 문제 정의

사용자(운영자) 체감: ETF쇼핑이 스노우볼 인컴보다 **폰트·컬러·메뉴 위치·반응형·아이콘 구성이 깔끔하다**.

실측 결론: 격차는 **구조가 아니라 표면**에 있다.

- 반응형(용도별 6단 브레이크포인트), 접근성(대비 CI 강제), 다크모드(8프리셋), SEO(크롤러 서버렌더+JSON-LD)는 **우리가 우위**.
- 뒤지는 것은 ①폰트의 브랜드 개성 ②컬러 역할 분리(특히 웜톤 부재) ③배경의 컬러풀함 ④내비 라벨의 기능감 ⑤**서비스를 소개하는 랜딩의 부재**(진입하자마자 도구가 나옴) — v2에서 ⑤ 추가.

## 3. 개선 트랙

### 트랙 ① 폰트 교체 ✅ 조합 확정 (2026-07-27 시안 비교로 결정)

- **확정 조합 (2026-07-27 최종 — 4역할)**:
  | 역할 | 서체 | 비고 |
  |---|---|---|
  | 본문·UI 한글 | **Wanted Sans** | OFL, 셀프호스팅 |
  | 헤딩·워드마크 | **Gmarket Sans** | 무료 상업(지마켓) |
  | 히어로 큰 숫자 (화면당 1곳) | **LINE Seed KR** | 무료 상업(LINE) |
  | **표·타일 데이터 숫자** | **Inter** | OFL, `tabular-nums`로 자릿수 정렬 |
- (SUIT·Freesentation·IBM Plex Mono·JetBrains Mono·Manrope 탈락, Pretendard는 교체 대상)
- **정렬 규칙**: 데이터 숫자는 Inter + `font-variant-numeric: tabular-nums`가 정본. 히어로 숫자는 정렬이 불필요한 자리만 LINE Seed KR.
- **라틴/한글 폴백 주의**: Inter는 한글 글리프가 없다 → 숫자 서체 스택은 반드시 `'Inter', 'Wanted Sans Variable', sans-serif` 순으로 두어 표 안 한글(예: "3종")이 Wanted Sans로 폴백되게 한다.
- 원칙 유지: 셀프호스팅(woff2 서브셋·CDN 금지), 라이선스 원문 재확인(LINE Seed KR = LINE 무료 상업 / Gmarket Sans = 지마켓 무료 상업), 8프리셋 라이트/다크 가독성 회귀 확인. 긴 본문(도움말·게시글)의 라운드 서체 피로도는 실화면 확인.

### 트랙 ④ 브랜드 워드마크 교체 ✅ 확정 (2026-07-27)

- **사용자 결정**:
  1. 워드마크 표기를 `Snowball Income` → **`스노우볼 인컴`** (한글)로 변경.
  2. **"스노우볼"과 "인컴"을 서로 다른 색**으로 (2색 워드마크). 
  3. **브랜드 아이콘(심볼)은 제거** — 텍스트 워드마크 단독.
- 참고: "눈덩이/스노우볼 비유 금지" 규칙은 **브랜드명 예외**에 해당(카피 금지 규칙 메모) — 워드마크 자체는 무관.
- **2색 배색 ✅ 최종 확정 (2026-07-27, C5 쿨 그라디언트)**: "눈이 굴러 자산이 되는" 서사를 쿨톤 그라디언트로 —
  - 라이트: 스노우볼 = `#3ba5d3→#79c5e6`(아이스 블루), 인컴 = `#0d9488→#22a06b`(틸→그린)
  - 다크: 스노우볼 = `#79c5e6→#aadcf2`, 인컴 = `#2dd4bf→#6ee7a0`
  - 구현: `background-clip: text` 그라디언트 텍스트. **그라디언트 불가 표면(OG 이미지 텍스트 폴백·파비콘·플레인 텍스트)의 정본 단색 폴백** = 스노우볼 `#3ba5d3` / 인컴 `#0d9488`(라이트 기준).
  - 액센트(구 골드 역할) = **틸/그린 축**(라이트 `#0d9488`·`#22a06b` / 다크 `#2dd4bf`·`#6ee7a0`). 8프리셋 대비 검증은 구현 게이트.
- 적용 범위: SimulatorHeader·PrimaryNav 브랜드 영역, TickerPageShell 헤더. ❓ 파비콘·OG 이미지·`site.webmanifest`는 별도 산출물이라 후속 여부 결정.

사용자 확정 와이어프레임:

```
┌─────────────────────────────────────────┐
│ 헤더:  [워드마크]   메뉴   검색   로그인      │   ← 트랙 ④ 워드마크, 검색 상시 노출
├─────────────────────────────────────────┤

├─────────────────────────────────────────┤
```

### 트랙 ⑧ 통합 검색 — 랜딩 히어로의 심장 ✅ 골격 확정 (2026-07-27)

메인(랜딩) 검색창의 동작. 사용자 확정 사양:

**입력 단계 (자동완성)**
- 검색어 입력에 **debounce**를 건 자동완성 — 타이핑 중 후보(티커·매칭 콘텐츠)를 드롭다운으로 제시.
- **결과 없음 폴백**: 검색어에 매칭되는 결과가 없으면 빈 화면 대신 **"관심 가져볼 만한 티커" 추천 카드**를 나열한다 (무결과 이탈 방지).
- ❓ debounce 값(자동완성 관례 250~300ms 권장), 추천 티커 선정 기준(인기 프리셋? 배당률 상위? 큐레이션 고정?).

**결과 단계 (자동완성 항목 클릭 또는 검색 실행)** — 3종을 **섞어서** 카드로 나열:

| # | 소스 | 내용 |
|---|---|---|
| 1 | 커뮤니티 포트폴리오 갤러리 | **해당 티커가 구성에 포함된** 배당 포트폴리오 카드들 |
| 2 | 게시판 | **해시태그(트랙 ⑨)가 검색어와 매칭**되는 게시글들 |
| 3 | ETF 소개(/ticker/*) | 검색어와 매칭되는 티커 소개 글 |

- ❓ 혼합 정렬 기준(소스별 고정 쿼터 vs 관련도 통합 정렬), 결과 페이지 경로(`/search?q=` 신설 권장).
- 데이터 주의: ①은 posts payload에서 티커 목록 추출(구성 JSON 파싱), ②는 트랙 ⑨ 선행 필요, ③은 정적 레지스트리 매칭이라 즉시 가능.
- 계측: 검색어·무결과율·소스별 클릭을 GA에 기록(다음 콘텐츠를 뭘 쓸지 §5.5의 근거가 된다).

### 트랙 ⑩ 시장 데이터 확장 — 환율 변동률·지수·한국 시장 ✅ 가용성 실측 완료 (2026-07-27)

**1) 원달러 환율 전일 대비 변동률 표기** (사용자 확정)
- 환율 위젯(ExchangeRateWidget)에 지난날 대비 상승/하락 %를 표기한다.
- 실측: Yahoo `KRW=X`를 `range=2d`로 부르면 당일가+전일 종가가 한 응답에 온다(무키) → 변동률 계산 가능. 현 FX 핸들러(open.er-api/frankfurter)는 당일 환율만 주므로, **`/api/fx`에 전일 종가 필드 추가**(Yahoo 병용 또는 frankfurter 날짜 API) 필요.

### 트랙 ⑬ 배당 가계부 — 실제 받은 배당의 개인화 기록 ✅ 방향 확정 (2026-07-27)

- **개념 정리** (기존 기획과의 관계):
  - 내 포트폴리오(진행 중) = "지금 보유 → **예상** 배당" (전망)
  - 배당 가계부(신규) = "실제로 **입금된** 배당 기록" (실적) — 기획 문서 `goal-achievement-system-plan.md` §2 "실제 배당 기록"의 구체화판이자, 트랙 ⑪-D(추정 vs 실측 비교 프레이밍)의 실행 지면
- **연동 설계 (핵심 가치)**:
  1. Portfolio 보유 종목·지급 예정월 → 가계부에 **기록할 행을 자동 프리필**("이번 달 SCHD 입금 예정 — 받으셨나요?") → 입력 최소화 철학 유지(금액만 적으면 됨)
  2. 예상(Portfolio) vs 실측(가계부) **나란히 비교** — 추정 정확도가 보이면 신뢰가 쌓인다(트랙 ⑪-D)
  3. 실측 누적이 쌓이면 **Goal "현재 월배당"의 최종 정본** 후보(시뮬 파생 → 보유 실측 → 입금 실측의 3단 진화 마지막 단)
  4. 배당 캘린더와 연결 — 지급일에 기록 유도
- **"재미" 장치 후보**: 월별·연도별 그래프, 누적 배당 카운터, 첫 배당·연속 기록 스트릭, 로드맵 v2 §10 Achievement(🥉첫 배당~💎월배당 100만원)와 직결. ❓ 게이미피케이션 수위.
- **결정 필요 ❓**: ①저장 위치(Portfolio 전용 DB 확장 vs 별도 스토어 — 연동 잦으니 같은 DB 스토어 분리 권장) ②통화(달러 입금 그대로 기록 + 원화 병기 권장 — 기획 §4 통화 정책 pm-po 확정 필요) ③경로(`/dividend/ledger`? 라벨 "배당 가계부") ④수동 입력 vs 프리필 확인 방식의 균형.
- 시점: Portfolio 도메인 랜딩 후 다음 미션 후보 1순위로 — 로드맵 v2 파이프라인(Portfolio → Goal)의 재방문 루프를 완성하는 조각.

### 3.5 클라우드 충돌 판정을 탭 단위로 (트랙 ⑯) — ✅ 방향 확정 (2026-07-28) · 4단계와 병렬 가능

> 문제: 서로 **다른 탭**을 각 기기에서 편집해도 "다른 기기에서도 편집했어요" 모달이 뜬다. 그리고 모달의 선택지가
> 로컬 전체 ↔ 클라우드 전체라, 어느 쪽을 골라도 **반대편 탭 편집이 통째로 사라진다**. UX 문제가 아니라 데이터 유실 경로다.

- **원인 (실측)**: `cloudWorkspaceSyncEngine.ts:239-240`이 `serializeMeaningfulPayload(payload) !== base`로 **payload 전체 문자열**을 base와 비교한다. 탭 id는 그 문자열 안 데이터일 뿐 비교 단위가 아니다 → 전부-아니면-전무 판정.
- **확정 방향 (사용자 A안)**: **base를 탭 단위로 기록**한다. 지금의 "payload 전체 직렬화 문자열 1개" → **`탭 id → 그 탭의 의미있는 직렬화` 맵**. 그러면 "어느 탭이 어느 쪽에서 변했는지"가 판정된다.
  - 겹치는 탭이 없으면 → **자동 블렌드**(모달 없음)
  - **같은 탭이 양쪽에서 변한 경우만** → 모달. 그것도 "이 탭 하나"로 범위가 좁아져 훨씬 친절해진다.
- **비용이 작은 이유 (실측)**:
  1. **id 기반 병합이 이미 있다** — `cloudWorkspaceReconcile.ts`의 "블렌드 병합"이 같은 id 쌍을 `isSameMeaningfulScenario`로 비교해 합집합·비파괴로 합친다(발산본엔 새 id 부여). 해결 로직은 검증돼 있고, **판정 단계만** 탭 단위로 바꾸면 된다.
  2. **비교 대상이 `{ scenarios: [...] }` 하나뿐이다**(`appStatePayloadDiff.ts:87`). 활성 탭·뷰 토글·최상위 미러·저장 이름은 이미 제외 → 탭 단위로 쪼개면 **비교 대상이 100% 덮인다**. "탭 밖 전역 설정 병합" 문제가 없다.
- **반드시 풀어야 할 케이스**: ①**삭제 vs 아직 없음** 구분(base에 있는데 한쪽에서 사라짐=삭제 / base에도 없음=신규 — 탭 단위 base면 자동 해결) ②같은 탭 양쪽 편집은 여전히 진짜 충돌(모달 범위만 축소) ③병합 후 활성 탭 결정 정책 ④**탭 상한 10개** 초과 시 규칙(발산본에 새 id를 주면 탭이 늘어난다).
- **제약**: base는 localStorage 부기값이라 스키마 마이그레이션이 아니다(구 형식=문자열이면 폴백 후 자동 재확립). 저장/공유 URL 스키마는 **무변경**. 하위 호환 왕복 테스트 필수.
- 담당: `state-engineer` 주도 + `qa-tester`(다기기 시나리오 결정론 테스트).

## 4.5 제품 심리 루프 ✅ 분석 확정 (2026-07-27) — 우선순위·설계 판단의 기준

```
[유입]  Lab 관음 콘텐츠(의원·버핏)·계산기형 광고·SEO(배당킹/ETF/검색)
   ↓ "이 포폴로 내 배당 계산" 다리 CTA (필수)
[정착]  내 포트폴리오 — 티커+수량 2입력 → 즉시 "내 월배당·달성률·다음 입금일"   ← HOOK
   ↓ 저장(투자 축적) + 배당일 내부 트리거
[습관]  캘린더 D-day → 입금 → 가계부 기록 → 스트릭·달성률 전진(goal-gradient)
   ↓ 기록 축적 = 이탈 비용 상승 (해자)
[확산]  달성 순간 공유 카드·갤러리 → 새 유입의 사회적 증거
```

- **재방문 주기 설계**: 매일(시세·환율 변동 = 가변 보상) / 매주(배당 입금 이벤트→기록 의식) / 매월(월초 "이번 달 예상" 리셋 + 달성률 전진). 주기마다 "열어볼 명분"이 재생산돼야 한다.
- **Hook의 정의**: "내 숫자가 즉시 나오는 순간"(티커+수량 → 3초 내 내 월배당). 시뮬레이터는 가정의 숫자라 유입용, 정착 hook은 Portfolio.
- **해자**: 가계부에 쌓인 본인 기록(IKEA 효과) — 기록이 쌓일수록 떠나기 어렵다.
- **광고 CTR 소재 뱅크** (심리 강도 순):
  1. "국회의원들이 가장 많이 보유한 주식 1위는?" — 호기심 갭+권력 관음+뉴스성
  2. "버핏이 이번 분기 전량 매도한 종목" — 권위+FOMO, 분기마다 소재 자동 재생산
  3. "월배당 50만원까지 몇 년? — 30초 계산" — 구체 숫자+자기 투영+즉시 보상
  4. "50년 연속 배당을 늘려온 미국 주식 전체 목록" — 안정 욕구+리스트 완결성
  5. "내 포트폴리오 월배당, 지금 얼마?" — CTR 중간·전환율 최고
  - ⚠ 원칙: 금액·수익 **약속이 아니라 계산·정보 약속**으로 쓴다(투자 자문 아님·과장 금지). 관음 소재(1·2)는 착지 페이지에 "내 배당 계산" 다리 없으면 이탈 — 다리 CTA가 광고 성과의 전제.
- **약한 고리 보정(실행 순서에 반영됨)**: [습관]→[확산] 트리거인 **공유 카드를 가계부 미션(6단계)에 포함**(기존 로드맵 후순위에서 승격) — 달성 순간에 제안해야 심리 효과가 산다.
