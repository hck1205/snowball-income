# 목표 달성 시스템 + 실제 배당 기록 — 기획 (사용자 방향 정리)

> 2026-07-26, 사용자가 직접 제시한 제품 방향을 정리한 문서.
> 배경: `feat/target-dividend-viz-v2`(PR #66, 머지됨)로 "목표 월배당 도달 시각화"가 나갔지만,
> 사용자가 원한 그림은 **차트 위 목표선을 넘어, 목표를 만들고 지속적으로 되돌아와 확인하는 시스템**이다.
> ROADMAP §1(목표 달성 시스템 ★★★★★, Phase 2)·§실제 배당 기록(★★★★☆, Phase 3)의 구체화판.

---

## 1. 목표 달성 시스템 (★★★★★)

### 목적

사용자가 투자 목표를 만들고 **지속적으로 진행 상황을 확인**할 수 있도록 한다.
(일회성 계산 → 기록·재방문 루프로 전환. ROADMAP 핵심 철학: "기록이 있는 서비스는 다시 방문한다")

### 목표 설정 — 4종

| 목표 유형 | 설명 |
|---|---|
| 목표 월배당 | 월 기준 배당 목표 금액 (현재 구현된 유일한 목표 축) |
| 목표 연배당 | 연 기준 배당 목표 금액 |
| 목표 FIRE | FIRE 기준 자산/현금흐름 목표 |
| 목표 은퇴 시점 | 언제까지 달성할 것인지 시점 목표 |

### 자동 계산 항목

- 현재 예상 월배당
- 목표 달성률
- **이번 달 증가량**
- **지난달 대비 증가율**
- 예상 목표 달성일 (월 해상도 — "2034년 8월")

> 주: "이번 달 증가량 / 지난달 대비 증가율"은 **시점 간 비교**가 필요하다.
> 즉 시뮬레이션 스냅샷(또는 포트폴리오 상태)의 **이력 저장**이 전제된다 — 현재 앱에는 없는 축.

### 대시보드 위젯 예시

```
🎯 목표 월배당

300만원

현재

92만원

달성률

31%

예상 달성

2034년 8월
```

### SNS 공유 카드 — 자동 생성

```
🎯 월배당 목표

300만원

현재

92만원

31%

이번 달

+32,000원
```

**공유 채널**: 커뮤니티 · 카카오 · X · Threads

## 2. 실제 배당 기록 (★★★★☆)

### 목적

예상 배당이 아닌 **실제로 받은 배당을 기록**한다.

### 입력 예시

```
7월

SCHD

$54

JEPI

$31
```

### 자동 생성

- 월별 그래프
- 연도별 그래프
- 누적 배당
- 목표 대비 진행률 (→ 목표 달성 시스템과 연결되는 지점: 목표 달성률의 "현재" 값을 예상치가 아닌 **실측치**로 채울 수 있다)

---

## 3. 현재 구현과의 갭 (2026-07-26 기준)

| 기획 항목 | 현재 상태 |
|---|---|
| 목표 월배당 설정 | ✅ 있음 (시뮬레이터 입력 + 차트 목표선·도달 마커·진행률 게이지, PR #66) |
| 목표 연배당 / FIRE / 은퇴 시점 | ❌ 없음 — 목표 축이 월배당 하나뿐 |
| 예상 달성 "연도" | ✅ 있음 (`findTargetYear`) |
| 예상 달성 "월" 해상도 | ❌ 없음 — 핸드오프 다음 미션 1순위, 스키마 무변경 파생 계산으로 가능 |
| 이번 달 증가량·지난달 대비 증가율 | ❌ 없음 — **이력 저장 개념 자체가 없음** (가장 큰 구조적 갭) |
| 목표 대시보드 위젯 (차트 밖 요약 카드) | ⚠️ 부분 — 진행률 게이지는 있으나 "위젯" 형태의 상시 요약은 아님 |
| SNS 공유 카드 자동 생성 | ❌ 없음 — 핸드오프 후보 3번 (별도 미션 크기) |
| 실제 배당 기록 | ❌ 없음 — 신규 도메인 (입력·저장·그래프) |

## 4. 구현 시 유의점 (팀 지식 기반)

- **영속 스키마 확장 필수**: 목표 4종·배당 기록 모두 저장 데이터 확장 → 하위 호환 왕복 테스트 필수 (기존 저장/공유 URL은 사용자 자산).
- **target ≤ 0 불변식 유지**: 목표 미설정이면 목표 관련 표기 전부 생략 (0원 목표 "달성" 버그 이력).
- **계산은 원화, 표시만 통화 전환** 원칙 유지. 실제 배당 기록은 $ 입력이 자연스러우므로(예시가 $) 기록 통화 정책을 pm-po 단계에서 확정할 것.
- SNS 공유 카드는 기존 og 카드 파이프라인(`api/og.js`, ogCard 재시뮬 경로) 재활용 가능성 검토.
- 카피에 "눈덩이/스노우볼" 비유 금지 (전 에이전트 공통 규칙).

## 5. 다음 단계 제안

1. **pm-po로 스코프 정의** (T3): 위 기획을 유저스토리·수용기준으로 분해. 특히 ①목표 4종의 우선순위 ②"이번 달 증가량"의 데이터 원천(시뮬 스냅샷 이력 vs 실제 배당 기록) ③실제 배당 기록과 목표 시스템의 결합 순서를 결정.
2. 착수 순서 후보: 예상 달성 월 해상도(작음, 즉시 가치) → 목표 축 확장 + 대시보드 위젯 → 실제 배당 기록 → SNS 공유 카드 순.
