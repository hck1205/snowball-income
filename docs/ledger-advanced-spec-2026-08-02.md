# Hippo 가계부 고도화 스펙 — 탭별 조회 · 외부 수정 확인 · 2인 블렌딩 · 배당 블렌딩

> 작성 2026-08-02 (트랙 B, pm-po). 사용자 원문 요청 4건을 구현 가능한 스펙으로 정의한다.
> 모든 `path:line` 은 2026-08-02 새벽 작업트리(브랜치 `feat/legal-and-ledger-enable`) 기준 실측이다.
> **사용자에게 물을 수 없는 세션**이라, 미결정 사항은 전부 여기서 결정하고 근거를 적었다.
> 뒤집기 비용이 낮게 설계했으므로(§7), 아침에 사용자가 다른 판단을 하면 해당 결정만 갈아끼우면 된다.

## 0. 사용자 원문 (요구 4건)

> 1. sheet의 탭별로 값을 가져올 수 있게 (B-1)
> 2. sheet에서 수정한 걸 확인하거나 화면에서 직접 수정 (B-2)
> 3. 가계부 2개(부부·연인)를 블렌딩하는 UI/UX (B-3)
> 4. 배당을 받고 있다면 배당 금액이 가계부에서 어떤 역할을 하는지 블렌딩 (B-4)

## 1. 문제 · 목표 · 비목표

### 문제

- 여러 탭(연도별·용도별)으로 가계부를 관리하는 사용자는 첫 탭만 연결된다 — 데이터 계층은 탭을 알지만
  (`ledger.ts:140`) UI 에 탭 선택이 없다.
- 시트에서 직접 고친 내용이 앱 화면에 언제 반영되는지 보이지 않는다(마지막으로 읽은 시각조차 화면에 없다).
- 2인 가구는 가계부가 두 개다 — 앱은 링크를 여러 개 저장하지만(`mapping.ts:111-230`) 한 번에 하나만 본다.
- 배당 투자자는 "배당이 내 생활비의 어디까지를 덮는가"를 이 앱 어디서도 볼 수 없다 — 포트폴리오 도메인이
  월 예상 배당을 이미 계산하는데도(`shared/lib/portfolio/PortfolioSummary.ts:171,197`).

### 목표

1. 스프레드시트의 **어느 탭이든** 골라 연결·전환할 수 있다 (B-1)
2. **시트 쪽 변경이 화면에 언제·어떻게 반영되는지**가 보인다 (B-2)
3. 두 가계부를 **한 화면에서 합쳐** 본다 — 출처 구분 포함 (B-3)
4. 포트폴리오의 예상 배당이 **가계부 맥락에서 숫자로** 읽힌다 (B-4)

### 성공지표 (가설 — GA 가계부 이벤트는 현재 0건, `shared/lib/analytics.ts` grep 실측)

| 지표 | 이벤트(신설 제안) | 파라미터 규율 |
|---|---|---|
| 탭 전환 사용 | `LEDGER_TAB_SWITCHED` | 값·ID·탭제목 미포함(준PII). 발생 여부만 |
| 새로고침 경로 분포 | `LEDGER_REFRESHED { trigger: 'manual' \| 'focus' }` | trigger 열거형만 |
| 블렌딩 도달 | `LEDGER_BLEND_VIEWED` | 파라미터 없음 |
| 배당 겹쳐 보기 채택 | `LEDGER_DIVIDEND_OVERLAY_TOGGLED { on: boolean }` | 불리언만 |

⚠ 이벤트 신설은 `ANALYTICS_EVENT` 택소노미(용도 주석 필수) 갱신 + analytics-analyst 검토 대상.
금액·시트 ID·파일명·탭 제목·열 이름은 **어떤 이벤트에도 싣지 않는다**(`sheetsApi.ts:7-8` 규율 2).

### 비목표 (이 스펙이 하지 않는 것)

- **인라인 셀 편집 · 일괄 편집 · 정렬 · 필터** — 화면 직접 수정은 이미 존재한다(§2). 정렬은
  "시트 순서 그대로"가 기존 결정이다(`useLedgerMonth.ts:44`). 이번에 뒤집지 않는다.
- **폴링** — 주기적 백그라운드 재조회는 만들지 않는다(배터리·429 할당량, §4 B-2 결정).
- **분류(category) 매핑표** — 두 가계부의 분류 체계를 앱이 통합·번역하지 않는다(§4 B-3 결정).
- **배당을 시트에 쓰기** — 배당은 화면 오버레이 전용이다(§4 B-4 결정, 이 스펙의 핵심 결정).
- **정밀 행 단위 변경 diff** — 물리 삭제로 행 번호가 밀리면(`types.ts:51-53`) 행 대응이 원리적으로
  불확실하다. "무엇이 몇 건 바뀌었다" 요약까지만 한다.
- **통화 변환·다국어 날짜 형식 지원** — 파싱 규칙은 기존 `parse.ts` 그대로. 실패 행은 이미
  `UnreadableRow` 로 관용 처리된다(`ledger.ts:188-192`).
- **가계부 행의 서버·로컬 저장** — "가계부 행은 사용자의 구글 시트에만 산다"(`config.ts:8-9`,
  decisions.md 2026-08-01)를 어떤 기능도 깨지 않는다.
- **제품명 리브랜딩** — 가계부 화면 안 카피는 "Hippo 가계부"를 쓰되(`ledgerCopy.ts` 기존 범위),
  그 밖(헤더·메타·법무)은 건드리지 않는다.

## 3. 공통 규율 (전 기능 적용 — 위반 시 리뷰 반려)

1. **가계부 행을 로컬·서버에 저장하지 않는다.** 로컬은 시트 ID + 탭 ID + 열 인덱스 (+ §4 B-3 의 라벨)뿐.
2. **탭 제목은 준PII — 저장·로그·GA 금지.** 연결할 때마다 메타에서 다시 읽는다(`mapping.ts:6`, `sheetsApi.ts:180-181`).
3. **에러 메시지에 값 금지** — 정적 문구만(`types.ts:148-157`).
4. **`snowball:ledger:links` 스키마는 이 스펙 전체에서 변경하지 않는다**(§7). 새 상태는 전부 새 키.
5. **수입·지출에 손익색 금지**(확정 결정), **색 단독 채널 금지**, **눈덩이 비유 금지**, **카피는 격식체**.
6. 문자열 리터럴은 화면에 박지 않는다 — 전부 `pages/Ledger/copy/ledgerCopy.ts`.
7. `writeSafety.ts` 의 규칙(스냅샷 참조·append 검증·충돌 비교)을 우회하는 코드 경로를 만들지 않는다.
8. 429 를 부르는 설계 금지 — 새 읽기 트리거는 전부 이 스펙에 명시된 것만(탭 전환 1회·수동 1회·포커스 복귀 스로틀).

## 4. 기능별 결정 · 유저스토리 · 수용기준

### B-1 탭별 조회

**유저스토리**: 연도별 탭으로 가계부를 관리하는 사용자로서, 연결한 스프레드시트의 다른 탭을 골라
그 탭의 내역을 보고 싶다. 탭마다 열 구성이 달라도 각각 한 번만 매핑하면 된다.

#### 결정

- **D1-1. 매핑은 탭 단위로 저장한다 — 이미 그렇게 돼 있으므로 스키마 변경 0.**
  `StoredSheetLink` 가 `spreadsheetId + sheetId` 단위이고(`mapping.ts:111-116`) `saveSheetLink` 가 같은
  조합만 덮어쓴다(`:203-216`). 탭 A 와 탭 B 는 서로 다른 저장 항목이 된다. 근거가 코드에 이미 있으니
  "스프레드시트 단위 매핑" 대안은 기각.
- **D1-2. 탭 전환 UI = 연결 정보 영역(연결됨 상태의 시트 정보 카드)에 네이티브 `<select>` 드롭다운.**
  - 월 네비 옆 기각: 탭은 "어느 장부"고 월은 "어느 기간" — 축이 다르다. 붙이면 "탭을 넘기면 달이
    넘어가나?"라는 혼동을 만든다.
  - 표 상단 가로 탭바 기각: 탭 20개에서 무너진다. 가로 스크롤 탭바가 항목을 숨기는 사고는 헤더 nav 에서
    이미 실측됐다(pitfalls 2026-07-31 NavScroller — 숨어도 아무 신호가 없다). `<select>` 는 20개든
    50개든 동일하게 동작하고 접근성이 공짜다.
  - 탭이 1개면 드롭다운 대신 탭 이름 텍스트만 표시한다(선택지가 없는 select 금지).
- **D1-3. 탭 전환 동작**: `connectSpreadsheet(ctx, { spreadsheetId, sheetId: 선택탭 })` 재호출.
  저장된 매핑이 있으면(`loadSheetLinks` 에서 조회) 즉시 `linked` → 스냅샷 재조회. 없으면 기존
  `needs-mapping` 매핑 세션(`useLedgerConnection.ts:328-342`)을 **그대로 재사용**한다. 성공 시
  `saveSheetLink` — 다음부터 그 탭은 원클릭.
- **D1-4. 탭 전환 시 월 커서는 유지한다**(두 탭에서 같은 달을 비교하는 것이 자연스러운 사용 흐름).
  단, **폼 모달이 열려 있거나 "저장하지 못한 기록" 대기열이 비어 있지 않으면 탭 전환을 비활성**하고
  이유를 문구로 보여 준다 — 대기열 항목의 재시도는 옛 링크·스냅샷을 향하므로(`useLedgerWrite.ts:243`,
  재시도가 `connection.link` 클로저를 씀) 탭이 바뀐 채 재시도하면 **다른 탭에 행이 추가되는 사고**가 난다.
- **D1-5. 탭 목록은 저장하지 않고(준PII), `connectSpreadsheet` 성공 반환에 `tabs` 를 추가로 실어 메모리에만 둔다.**
  현재는 메타를 읽고 버린다(`ledger.ts:137-141`). UI 가 `fetchSpreadsheetMeta` 를 따로 또 부르면
  연결마다 요청이 1회 늘어난다(429 예산). `ConnectionOutcome` 의 두 분기 모두에 `tabs: readonly
  SheetTabMeta[]` 를 **추가만** 한다(기존 필드 불변 — 기존 테스트는 필드 추가에 깨지지 않아야 정상).

#### 수용기준

- AC1-1. 탭이 2개 이상인 시트를 연결하면, 연결 정보 영역에 현재 탭 이름과 탭 선택 드롭다운이 보인다.
  탭이 1개면 드롭다운이 없다.
- AC1-2. 저장된 매핑이 있는 탭으로 전환하면 추가 매핑 화면 없이 그 탭의 내역이 표시된다.
- AC1-3. 저장된 매핑이 없는 탭으로 전환하면 열 매핑 화면이 뜨고, 확정하면 그 탭이 연결되며
  `snowball:ledger:links` 에 그 탭의 항목이 **추가**된다(기존 탭 항목은 그대로 남는다).
- AC1-4. 탭 전환 후에도 보고 있던 월(커서)이 유지된다.
- AC1-5. 폼 모달이 열려 있거나 저장 실패 대기열이 있으면 탭 선택이 비활성화되고, 비활성 사유가
  텍스트로 표시된다.
- AC1-6. 탭 전환으로 만들어진 새 스냅샷 이전의 행 참조로는 쓰기가 실행되지 않는다
  (기존 `guardRowRef` 경로 — 회귀 확인).
- AC1-7. 탭 제목이 `localStorage`·GA 이벤트·에러 메시지 어디에도 저장·전송되지 않는다
  (기존 소스 가드 `test/ledger/ledgerSourceRules.test.ts` 관례에 맞춰 검사 추가).
- AC1-8. **하위 호환 왕복**: 기능 배포 전 형식의 `snowball:ledger:links` 페이로드(탭 1개 시절 항목)를
  넣고 로드 → 연결 → 재저장해도 항목이 유실·변형되지 않는다.

### B-2 외부 수정 확인 (+ 화면 직접 수정)

**유저스토리**: 시트를 폰에서 고치고 앱으로 돌아온 사용자로서, 내가 보는 화면이 시트의 최신 상태인지,
언제 읽은 것인지 알고 싶다. 오래된 화면이면 앱이 알아서 다시 읽어 주면 좋겠다.

#### 결정

- **D2-1. "화면에서 직접 수정"은 이미 있다 — 이번 스코프는 "확인" 쪽 공백만 메운다.**
  수정 모달·필드 단위 패치·충돌 감지·실패 잔류가 전부 구현돼 있다(`useLedgerWrite.ts:250-268`,
  `LedgerFormModal`). 없는 것은 ①상시 새로고침 버튼 ②마지막으로 읽은 시각 표시 ③돌아왔을 때의
  자동 확인 — 이 3개만 만든다. 인라인 편집은 비목표(§1).
- **D2-2. 폴링하지 않는다. 자동 확인은 "창 포커스 복귀 + 마지막 읽기에서 5분 경과" 조건에서만.**
  - 폴링 기각 근거: Sheets 읽기는 429 가 실제로 나는 자원이고(`useLedgerMonth.ts:42-43` 주석 —
    "달을 넘길 때마다 네트워크를 때리면 429 에 바로 닿는다"), 폴링은 탭을 열어 둔 것만으로 할당량과
    배터리를 태운다.
  - 5분 스로틀은 기존 관례를 따른다(주요 지수 탭 복귀 5분 — `docs/external-data.md` §3-1).
  - 포커스 복귀 확인은 폼 모달·삭제 다이얼로그가 열려 있으면 하지 않는다(입력 중 스냅샷 교체 금지 —
    수정 충돌은 어차피 `seen` 비교가 잡지만, 화면이 사용자 밑에서 바뀌는 경험 자체를 피한다).
- **D2-3. 변경 감지는 "요약 비교"까지만.** 재조회 후 직전 스냅샷과 (건수, 행별 `seen` 값 집합)을
  메모리에서 비교해 달라졌으면 "시트 내용이 갱신되었습니다" 성 안내를 라이브 리전 + 1줄 문구로 낸다.
  행 단위 정밀 diff 는 비목표 — 물리 삭제가 행 번호를 밀면(`types.ts:51-53`) 옛 행과 새 행의 대응이
  원리적으로 불확실해서, 정확한 척하는 diff 는 날조 금지 원칙에 걸린다.
- **D2-4. 표시 위치**: 목록 카드(`copy.list.title`) 헤더 우측에 "새로고침" 보조 버튼 + "HH:MM 기준"
  텍스트(= `readAt`). 재조회 중에는 기존 `isRefetching` 시각 신호를 그대로 쓴다.

#### 수용기준

- AC2-1. 연결된 목록 화면에 마지막으로 읽은 시각이 표시되고, 새로고침 성공 시 갱신된다.
- AC2-2. 새로고침 버튼 클릭 시 스냅샷이 재조회되고, 시트에서 바뀐 값(예: 금액 수정)이 목록에 반영된다.
- AC2-3. 창 포커스 복귀 시 마지막 읽기에서 5분이 지났으면 자동 재조회되고, 5분 미만이면 요청이 발생하지
  않는다(모의 fetch 호출 횟수로 단정).
- AC2-4. 폼 모달 또는 삭제 다이얼로그가 열려 있는 동안에는 포커스 복귀 자동 재조회가 발생하지 않는다.
- AC2-5. 재조회 결과가 직전과 다르면(행 추가·값 변경·행 감소) 갱신 안내 문구가 표시되고 라이브 리전으로
  읽힌다. 같으면 안내가 나오지 않는다.
- AC2-6. 429 실패 시 새로고침 버튼이 기존 `rate-limited` 문구·카운트다운 규약을 따른다(연타 유도 금지).
- AC2-7. 자동 재조회가 열려 있는 월 커서를 바꾸지 않는다.

### B-3 가계부 2개 블렌딩 (부부·연인)

**유저스토리**: 배우자와 가계부를 따로 쓰는 사용자로서, 두 가계부를 한 화면에서 합쳐 "우리 가계"의
월 수입·지출을 보고 싶다. 어느 항목이 누구의 기록인지도 구분하고 싶다.

#### 결정

- **D3-1. 권장 경로 = "한 스프레드시트에 탭 2개".** B-1 이 끝나면 부부가 시트 하나를 공유하고 각자
  탭을 쓰는 구성은 **추가 권한 문제 없이** 즉시 성립한다(`drive.file` 파일 1개 권한으로 두 탭 모두 접근).
  블렌딩 기능은 링크 2개를 합치는 것으로 설계하되, 두 링크가 같은 파일의 두 탭이든 다른 파일이든
  동일하게 동작한다 — 그래서 권한 리스크가 기능 전체를 막지 못한다.
- **D3-2. 별개 파일 경로의 권한 전제 — 원리는 성립, 화면 노출은 미확인(실측 필요).**
  - 확인된 사실: `drive.file` 에서 기존 시트를 여는 유일한 길은 피커다(URL 붙여넣기 불가 —
    `picker.ts:4-6` 주석). 피커로 고른 파일에는 소유 여부와 무관하게 앱 접근권이 부여되는 것이
    `drive.file` + Picker 의 설계다(같은 주석: "사용자가 피커로 고른 파일").
  - **미확인**: 현재 피커 뷰 구성(`DocsView(ViewId.SPREADSHEETS)`, `setIncludeFolders(false)` —
    `picker.ts:185-188`)이 **"공유 문서함"(상대가 공유해 준 파일)을 목록에 노출하는지**. 이 세션에서는
    실제 구글 계정 2개로 실측할 수 없었다. `docs/external-data.md` 에도 이 항목의 스파이크 기록은 없다.
  - 따라서 트랙 첫 작업 = **실측 스파이크**(계정 2개, 상대 소유 시트를 공유받아 피커에서 선택 시도).
    성공 → 별개 파일 경로 정식 지원. 실패 → V1 은 "같은 파일 탭 2개" 경로만 안내하고, 피커 뷰 구성
    변경(공유 문서함 뷰 추가)을 후속 검토로 넘긴다. **어느 쪽이든 블렌딩 코어는 동일하다.**
- **D3-3. 신원 모델·저장: 새 로컬 키 `snowball:ledger:blend` (v1, 단일 객체).**
  ```
  { version: 1,
    a: { spreadsheetId, sheetId, label },   // label = 사용자가 붙인 이름, 기본 '가계부 1'
    b: { spreadsheetId, sheetId, label } }  // 기본 '가계부 2'
  ```
  - `snowball:ledger:links` 는 **한 글자도 바꾸지 않는다.** 블렌딩 구성은 links 의 두 항목을
    가리키는 참조일 뿐이다. 가리키는 링크가 links 에 없으면 그 구성은 무효로 조용히 버린다
    (`parseStoredSheetLinks` 와 같은 관용 원칙).
  - 라벨은 사용자가 스스로 붙이는 이름이다(예: "나", "배우자"). 시트 파일명·탭 제목을 라벨 기본값으로
    **쓰지 않는다**(준PII 를 저장하게 되는 뒷문이 된다). 기본값은 중립 문구 '가계부 1/2'.
- **D3-4. 블렌딩 뷰 = 읽기 전용 통합 월 뷰.**
  - 두 링크의 스냅샷을 각각 1회씩 읽어(총 2요청) 메모리에서 합친다. 월 필터·정렬 원칙은 단일 뷰와 동일
    (재조회 없이 메모리 필터, 시트 순서 유지 — 통합 목록은 날짜 없이 섞이면 못 읽으므로 **날짜 오름차순
    안정 정렬만 예외로 허용**하되, 원본 시트는 여전히 건드리지 않는다).
  - 각 행에 출처 라벨 배지(라벨 **텍스트** + 테두리 모양 차이 — 색 단독 채널 금지).
  - 월 요약: 합산 3숫자(수입·지출·합계, 손익색 금지 기존 규약 유지) + **출처별 소계 2줄**
    ("가계부 1: 수입 X · 지출 Y") — "누가 얼마 썼는지"는 이 소계가 답한다. 행 단위 귀속은 배지가 답한다.
  - **쓰기(추가·수정·삭제)는 블렌딩 뷰에서 하지 않는다.** 쓰기 안전 체계(스냅샷 참조·충돌 비교)가 링크
    단위로 설계돼 있어(`ledger.ts:1-8`) 두 링크가 섞인 화면의 쓰기는 "어느 시트에 쓰나"부터 오류 표면이
    두 배가 된다. V1 은 읽기 전용, 각 행의 수정은 해당 가계부의 단일 뷰로 전환해서 한다(전환 버튼 제공).
- **D3-5. 분류는 합치지 않는다.** 두 가계부의 분류 문자열을 원문 그대로 표시하고 출처로 구분한다.
  매핑표는 유지보수 비용(분류 개편 때마다 재매핑)이 효용을 넘는다 — 비목표. 분류별 집계가 필요해지면
  "같은 문자열 = 같은 분류"의 소박한 규칙으로 시작할 수 있게 자리만 남긴다.
- **D3-6. 통화·날짜 형식**: 기존 파싱 규칙 그대로. 형식이 다른 행은 이미 `UnreadableRow` 로 건너뛰고
  보고된다 — 블렌딩 뷰도 두 시트의 읽지 못한 행 수를 출처별로 표시한다. 통화 변환은 하지 않는다
  (가계부는 금액 숫자를 그대로 더한다 — 두 시트가 다른 통화면 합계가 무의미해지는데, 이를 앱이 감지할
  방법이 없으므로 도움말 문구로 "두 가계부는 같은 통화를 전제합니다"를 명시한다).
- **D3-7. 한쪽만 연결 = 정상 상태.** 블렌딩 진입점(토글/버튼)은 저장된 링크가 2개 이상일 때만 노출.
  블렌딩 중 한쪽 읽기가 실패하면 **반쪽 데이터로 합계를 내지 않는다** — 실패한 쪽을 명시하고 성공한
  쪽만 단일 뷰 수준으로 보여 주며 합산 요약은 "불러오지 못함"(날조 금지).
- **D3-8. 프라이버시**: 상대 가계부 행은 내 행과 동일하게 **메모리에만** 있다. 로컬에 남는 것은
  시트 ID·탭 ID·매핑·사용자 라벨뿐. GA 는 `LEDGER_BLEND_VIEWED` 발생 여부만. 에러 메시지 정적 문구
  규율 동일 적용.

#### 수용기준

- AC3-1. 저장된 링크가 2개 이상이면 블렌딩 진입점이 보이고, 1개 이하면 보이지 않는다.
- AC3-2. 블렌딩 구성(두 링크 선택 + 라벨)이 새 키 `snowball:ledger:blend` 에 저장되고,
  `snowball:ledger:links` 의 직렬화 결과는 블렌딩 사용 전후로 **바이트 동일**하다.
- AC3-3. 블렌딩 뷰에서 두 가계부의 같은 달 항목이 날짜 오름차순으로 합쳐 표시되고, 각 행에 출처
  라벨이 텍스트로 표시된다.
- AC3-4. 월 요약이 합산 3숫자와 출처별 소계를 보여 주고, 합산 = 소계의 합이다(속성 테스트 가능).
- AC3-5. 한쪽 스냅샷 읽기 실패 시 합산 숫자가 표시되지 않고(0 으로 채우지 않는다), 실패한 가계부와
  복구 경로(기존 `LedgerRecovery` 규약)가 표시된다.
- AC3-6. 블렌딩 뷰에 추가·수정·삭제 버튼이 없고, 행에서 "이 가계부에서 열기" 경로로 단일 뷰 전환이 된다.
- AC3-7. 블렌딩 구성이 가리키는 링크를 `removeSheetLink` 로 지우면 블렌딩 구성이 무효 처리되고
  화면이 단일 가계부 상태로 돌아간다(고아 참조로 크래시하지 않는다).
- AC3-8. 왕복: 블렌딩 구성 저장 → 새로고침(재로드) → 같은 구성 복원. 불량 페이로드(임의 JSON) →
  조용히 무시하고 블렌딩 꺼짐.
- AC3-9. 라벨·시트 ID·금액이 GA 이벤트와 에러 문구에 실리지 않는다(소스 가드 확장).
- AC3-10. (스파이크 산출) 공유받은 타인 소유 시트가 피커에서 선택 가능한지 실측 결과가 이 문서
  §8 리스크 표에 기록된다 — 성공/실패 각각의 후속 경로는 D3-2 에 이미 정의돼 있다.

### B-4 배당 블렌딩 (배당이 가계부에서 하는 역할)

**유저스토리**: 배당 투자를 하며 가계부를 쓰는 사용자로서, 이번 달 예상 배당이 내 지출의 어디까지를
덮는지 가계부 화면에서 바로 보고 싶다.

#### 결정

- **D4-1. 배당 출처 = 포트폴리오 도메인의 실보유 (`pages/Portfolio` + `shared/lib/portfolio`).**
  - 채택 근거: 유일하게 "사용자가 실제로 가진 수량"에서 나온 숫자다. `computePortfolioSummary` 가
    이번 달 예상 배당(`thisMonthDividendUsd`, 지급월을 아는 종목만 계상 — `PortfolioSummary.ts:171,185-186`)과
    세후 환산(`:195-196`)을 이미 제공한다. **이 라이브러리를 읽기만 하고 수정하지 않는다.**
  - 기각: 시뮬레이터 상태(`jotai/snowball/atoms/portfolio`)는 가설 시나리오의 구성이지 보유가 아니다.
    배당 캘린더는 지급월 데이터의 출처일 뿐 금액 주체가 아니다(이미 PortfolioSummary 가 소비한다).
  - **"배당을 받고 있는 상태"를 앱이 아는 방법**: 포트폴리오에 수량 > 0 이고 시장정보가 해석되는 보유가
    있으면 "예상 배당이 있다"고 본다. 그 이상(실제 입금 여부)은 앱이 알 수 없다 — 그래서 모든 카피가
    **"예상 배당(내 포트폴리오 기준)"** 이라고 말하고, 실수령처럼 표현하지 않는다(날조 금지).
    포트폴리오가 비어 있으면 카드 자체가 안내 1줄("포트폴리오에 보유 수량을 입력하면 …")로 대체된다.
- **D4-2. 배당은 시트에 쓰지 않는다 — 화면 오버레이 전용. (이 기능의 핵심 결정)**
  | | 시트에 쓴다 | 화면에서만 겹친다(채택) |
  |---|---|---|
  | 사용자 시트 | **오염** — 앱이 추정치를 사용자 자산에 기입 | 무변경 |
  | 이중 계상 | 사용자가 실제 입금을 이미 기록했으면 **중복** | 없음(요약 숫자에 합산 안 함) |
  | 철회 | 쓴 행을 되짚어 지워야 함(사실상 불가) | 토글 끄면 끝 |
  | "가계부 총합" 정의 | 시트 총합 = 앱 총합 유지 | 둘이 될 위험 → **아래 규칙으로 차단** |
  - "총합 정의 둘" 문제의 해법: **월 요약 3숫자(수입·지출·합계)에는 배당을 절대 합산하지 않는다.**
    배당은 요약 카드와 분리된 **별도 카드**에만 나타난다. 가계부의 총합 정의는 하나로 유지된다.
- **D4-3. 지표 3개 (전부 "이번 달 · 보고 있는 월" 기준, 세후 KRW):**
  1. **이번 달 예상 배당** — `thisMonthDividendUsd` 의 세후·원화 환산. 지급월 미상 종목이 있으면
     "지급월 미상 N종은 포함되지 않습니다" 를 함께 표시(현재 유니버스 29종이 미상 —
     `docs/external-data.md` §2 커버리지).
  2. **지출 커버율** — 예상 배당(세후 KRW) ÷ 보고 있는 달의 지출 합계. 지출이 0 이면 표시하지 않는다
     (0 나눗셈을 100%로 위장 금지).
  3. **배당이 감당하는 분류** — 그 달 지출을 분류별 합계로 접고, 작은 분류부터 누적해 예상 배당(세후)
     이내에 들어오는 분류 이름을 나열("통신비·구독료를 덮습니다" 식). 하나도 못 덮으면 커버율만 표시.
  - 원화 환산은 기존 FX 상태(`jotai/snowball/atoms/fx`)를 **구독만** 한다 — 표시 전용 원칙 그대로
    (`docs/external-data.md` §3 절대 규칙). 환율이 `success/stale` 이 아니면 **환산·커버율을 표시하지
    않고** "환율을 불러오지 못해 원화 환산을 표시할 수 없습니다" + USD 원값만 보여 준다.
- **D4-4. 기본 꺼짐 토글 "배당 겹쳐 보기".** 상태는 새 로컬 키 `snowball:ledger:dividend-overlay`
  (`'on' | 'off'`, 없으면 off). 배당 카드는 요약 카드 아래 형제 카드로 배치(Card 중첩 금지 규약 —
  `LedgerPage.view.tsx:455` 주석과 동일).
- **D4-5. 표현 규율**: 수입·지출 손익색 금지 규약을 배당 카드에도 적용(중립 톤). "눈덩이" 금지.
  블렌딩(B-3) 화면에서는 V1 에서 배당 카드를 **표시하지 않는다** — "우리 가계" 대비 "내 포트폴리오"의
  귀속 혼선(배당은 한 사람 것)을 V1 에서 풀지 않는다.

#### 수용기준

- AC4-1. 토글 기본값은 꺼짐이고, 켜면 배당 카드가 나타나며, 상태가 재방문 시 유지된다.
- AC4-2. 배당 카드가 켜져도 월 요약 3숫자(수입·지출·합계)는 토글 전후 동일하다(합산 금지 단정).
- AC4-3. 시트 쓰기 API(`writeValues`·`deleteRow`)가 배당 기능 경로에서 한 번도 호출되지 않는다
  (모의 컨텍스트로 단정).
- AC4-4. 포트폴리오 보유가 없으면 지표 대신 안내 문구가 표시되고, 어떤 숫자도 0 으로 위장되지 않는다.
- AC4-5. 환율 미가용 상태에서 원화 환산·커버율이 숨고 USD 원값과 안내 문구가 표시된다.
- AC4-6. 지출 합계가 0 인 달에는 커버율이 표시되지 않는다.
- AC4-7. 지급월 미상 종목이 포함된 포트폴리오에서는 "포함되지 않음" 안내가 표시된다.
- AC4-8. 카드의 모든 문구가 "예상"임을 명시하고, 손익색 토큰(data-positive/negative)이 카드에 없다.

## 5. 우선순위 · 의존 · 배치 계획

### 의존 그래프

```
B-1 탭별 조회 ──────────► B-3 블렌딩 (탭 전환·다중 링크 UI 재사용 + "같은 파일 탭 2개" 권장 경로)
B-2 신선도(독립)              │
B-4 배당 카드(독립)           └─ 실측 스파이크(피커 공유파일) 는 B-3 코드와 무관하게 먼저 가능
```

우선순위 근거: ① B-1 은 나머지의 토대이며 스키마 변경 0 으로 가장 싸다. ② B-2 는 "시트가 진실"인
이 설계에서 신뢰의 핵심이라 두 번째. ③ B-4 는 독립적이고 오버레이 전용이라 리스크가 낮다.
④ B-3 은 가장 크고 실측 전제가 있어 마지막 — 단 스파이크는 병렬로 먼저.

### 트랙 분할과 파일 소유권 (경로 단위 — 병렬 충돌 방지의 유일한 수단)

| 트랙 | 담당 | 소유 경로(쓰기 권한) | 산출물 |
|---|---|---|---|
| **L1 (B-1)** | state-engineer → frontend-engineer | `shared/lib/googleSheets/ledger.ts`(tabs 추가만) · `pages/Ledger/hooks/useLedgerConnection.ts` · `pages/Ledger/components/LedgerTabPicker/`(신설) · `pages/Ledger/components/LedgerConnectPanel/` · `pages/Ledger/copy/` · `pages/Ledger/types/` · `test/ledger/` `test/googleSheets/` 해당 케이스 | 탭 선택·전환 |
| **L2 (B-2)** | frontend-engineer | `pages/Ledger/hooks/useLedgerFreshness.ts`(신설) · `pages/Ledger/LedgerPage/`(뷰·컨테이너) · copy 추가 절 | 새로고침·읽은시각·포커스 확인 |
| **L3 (B-3)** | ui-ux-designer(설계) → state-engineer(저장·병합 순수함수) → frontend-engineer | `pages/Ledger/utils/ledgerBlend.ts`(신설) · `pages/Ledger/hooks/useLedgerBlend.ts`(신설) · `pages/Ledger/components/LedgerBlendSetup/` `LedgerBlendView/`(신설) | 블렌딩 |
| **L4 (B-4)** | frontend-engineer | `pages/Ledger/utils/ledgerDividend.ts`(신설) · `pages/Ledger/components/LedgerDividendCard/`(신설) | 배당 카드 (**`shared/lib/portfolio` 는 읽기 전용**) |
| 공통 | qa-tester | `test/ledger/` 신설 파일 | AC → 테스트 |

- 🔴 **`pages/Ledger/LedgerPage/LedgerPage.view.tsx` 는 공유 병목이다** — 배선(신규 컴포넌트 삽입)은
  L1 → L2 → L4 → L3 순서로 **순차** 진행한다. L3·L4 는 자기 컴포넌트 폴더에서 병렬로 만들고 배선만
  순번을 기다린다.
- 🔴 `shared/lib/googleSheets/` 는 L1 의 `ConnectionOutcome.tabs` 추가 **한 건 외에 수정 금지**
  (writeSafety·mapping·sheetsApi 불가침).
- 실행 순서 제안: **1일차 = L1 + L2 + (B-3 실측 스파이크 병렬)** → 검증 → **2일차 = L4 → L3**.
- 각 트랙 종료 시 `npx vitest run test/ledger test/googleSheets`, 배치 종료 시 `npm run test` 전량 1회.
  `npm run api:bundle` 은 트랙 중 실행 금지(브리핑 §5).

### 컷라인 — "어디까지 하면 되돌릴 필요가 없나"

**L1 + L2 에서 끊어도 완결이다.** 이 지점까지는 ①localStorage 스키마 변경 0 ②새 키 0 ③데이터 계층
변경은 additive 반환 필드 1개뿐 ④기존 화면 동작 전부 보존. 사용자가 아침에 방향을 바꿔도 되돌릴 것이
없다. L3·L4 는 각각 새 키 1개 + 신규 컴포넌트뿐이라 어느 시점에 끊어도 기존 사용자를 깨지 않는다.
